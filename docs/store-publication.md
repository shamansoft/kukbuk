# Publish Save-A-Recipe on Chrome and Firefox

Use this checklist for the desktop release after the packaging, page-access, and disclosure changes are merged. Work through the steps in order. Keep the tested ZIPs and matching Firefox source together until both reviews finish.

1. **Set up publisher accounts.** Sign in to the Chrome Web Store Developer Dashboard and the Mozilla Add-on Developer Hub. Complete their registration and account verification prompts. Choose a support email you monitor. For an update, open the existing item to preserve its installed users and identifier. [Chrome publishing](https://developer.chrome.com/docs/webstore/publish) · [Mozilla submissions](https://extensionworkshop.com/documentation/publish/submitting-an-add-on/)
2. **Configure authentication for the final IDs.** For a new Chrome item, reserve its item ID using a dashboard draft before testing the final OAuth setup. In Google Cloud, associate the Chrome extension OAuth client with that ID. In Firebase, enable the sign-in methods you offer. If offering Google sign-in on Firefox, register the exact redirect URI for the stable Gecko ID on the Web application OAuth client. Supply its public client ID to the release build. If you ship email-only on Firefox, verify that the Google button stays hidden. Keep client secrets and reviewer passwords out of ZIPs. [Firefox redirect setup](../README.MD#enable-google-sign-in-in-firefox) · [Chrome extension ID](https://developer.chrome.com/docs/extensions/reference/manifest/key)
3. **Verify what the service does with data.** With whoever operates Save-A-Recipe, trace a page save and a typed description through Firebase, the recipe API, processing services, connected storage, and server logs. Record the data each party receives, why it needs it, retention periods, access, and deletion steps. If a model provider processes recipe content, confirm its actual retention and training settings. Check what signing out, disconnecting storage, and deleting an account each do.
4. **Publish the privacy policy on a public HTTPS page you control.** Identify the operator and contact, account/profile and authentication information, selected-page URL, title, and cleaned HTML that can include text outside the recipe, typed descriptions, each recipient, and the practices verified in step 3. Include the applicable Chrome Limited Use commitment once verified. Open the URL while signed out. Use that same URL in both listings. [Chrome user-data rules](https://developer.chrome.com/docs/webstore/program-policies/policies#protecting-user-privacy) · [Mozilla data rules](https://extensionworkshop.com/documentation/publish/add-on-policies/)
5. **Prepare the release and reviewer account.** Build both store ZIPs from the same final revision using the release configuration. Collect the Firefox source archive and clean-build instructions. Check the manifest versions and IDs inside both ZIPs. Create a dedicated verified test account with connected storage, sample data, and enough quota. Confirm a reviewer can sign in without access to your phone or inbox. Share its credentials only through each store’s private reviewer fields.
6. **Test the exact upload files.** In clean desktop browser profiles, extract the Chrome ZIP and load its directory using Load unpacked (verify the OAuth ID matches the store ID). Temporarily load the Firefox package through about:debugging. Sign in, save a public recipe via the toolbar (including a sample without structured recipe markup), open the saved result, and create another recipe via the toolbar context menu. Try a non-recipe page, cancel a sign-in, retry, and sign out. Repeat for each storage destination and sign-in method you will advertise. Check the network request on a sample page with a dummy hidden field and URL fragment. Confirm neither value is transmitted. Record the public test URL and expected output for reviewers.
7. **Complete the Chrome listing.** Upload the tested Chrome ZIP. Add the icon, current screenshots, support contact, category, and distribution settings. Describe the single purpose as saving recipes from a selected page or written description to connected storage. Prominently explain that clicking the toolbar button sends the selected page’s URL, title, and cleaned HTML to Save-A-Recipe for recipe detection, along with sign-in and storage prerequisites, and any payment requirements. In Privacy practices, declare the actual account identifiers, authentication information, visited URL, and website content. Explain each requested permission and host using the final manifest. Describe Firebase authentication accurately in the remote-code declaration. Add the policy URL, complete the certifications, and supply private test instructions and credentials. [Chrome dashboard privacy fields](https://developer.chrome.com/docs/webstore/cws-dashboard-privacy)
8. **Complete the Mozilla listing.** Choose distribution on addons.mozilla.org, upload the tested Firefox ZIP, and supply the original source and reproduction instructions for the webpack bundle. Select desktop Firefox for this release. Check the install-time data categories against the policy and the package. Read each validator finding, including Android compatibility notices if shown. Add the same data-transfer description, screenshots, prerequisites, policy URL, support contact, and private testing details. [AMO submission walkthrough](https://extensionworkshop.com/documentation/publish/submitting-an-add-on/) · [Source requirements](https://extensionworkshop.com/documentation/publish/source-code-submission/)
9. **Submit and follow up.** Preview the public listings, submit each item for review, and monitor both dashboards and the publisher inbox. For submissions on or after December 1, 2026, check Mozilla’s policy update. After approval, install from each store in a fresh profile and repeat the sign-in and save checks with the store-assigned identity. Rotate reviewer credentials once review is finished and refresh them before the next review. [Chrome policies](https://developer.chrome.com/docs/webstore/program-policies/policies) · [Mozilla policies and upcoming changes](https://extensionworkshop.com/documentation/publish/add-on-policies/)
